### 文書をどこに置くか — 制約から決まった設計

当初は「文書をドキュメントルート外 (`doc_details/`) に置き、PHP が読んで描画する」
設計にした。`.md` が Web から直接取得される経路が存在しないので堅い。
ところが実際に試すと**読めなかった**。

```
$ ls -ld /home/sanuki
drwxr-x--- 21 sanuki sanuki   /home/sanuki
```

Apache は `www-data` で動くので `/home/sanuki` を**辿れない**。
`is_readable()` が `false`、`glob()` が 0 件になる。

取れる手は 3 つあった。

1. `chmod o+x /home/sanuki` で辿れるようにする
   → 利用者のホームディレクトリの権限を変えることになるので採らなかった
2. `content/` に生の `.md` を置く
   → `AllowOverride None` で `.htaccess` が使えないため
     **パスワードなしで直接読める**。要件を満たさない
3. `.md` を**定数ガード付きの nowdoc で PHP に包む**  ← これを採った

3 の中身はこうである。

```php
<?php
if (!defined('SYNTHLAB_DEV')) { http_response_code(404); exit; }
return <<<'SYNTHLAB_MD_EOF'
（Markdown 本文）
SYNTHLAB_MD_EOF;
```

- `doc.php` は `SYNTHLAB_DEV` を定義してから `require` するので中身が読める
- 直接 HTTP で叩くと定数が未定義なので **404 を返して何も出力しない**
- **nowdoc** (`<<<'DELIM'`) にするのが必須。文書は `$\mu$` のように `$` を多用するので、
  heredoc だと変数展開されて壊れる

正本は `doc_details/*.md` のまま。`tools/publish-docs.php` が包んで配置する。
区切り子が本文中に現れないことを検査し、包んだものを読み戻して原文と一致するか
**往復検証**してから書き出すので、壊れた場合は非ゼロ終了する。

実測での確認:

```
GET /synthlab_dev/content/05-algorithm.md.php  → 404, 0 bytes
GET /synthlab_dev/config.php                   → 404
GET /synthlab_dev/content/                     → 404 (index.php を置いて一覧を抑止)
```

## 2. パスワード保護の実装方針

**制約**: `/etc/apache2/apache2.conf` の `/var/www/` ブロックが
`AllowOverride None` であり、パスワードなしの sudo も通らないため
**`.htaccess` による Basic 認証は使えない**。
`auth_basic` / `authn_file` モジュール自体は有効なので、
`sudo` が使える環境では `AllowOverride AuthConfig` に変えれば移行できる
(手順は README)。

そこで PHP セッションによる認証にした。

```php
// 保護対象ページの先頭
require_once __DIR__ . '/auth.php';
dev_require_login();
```

- パスワードは `password_hash()` のハッシュのみ保存。**平文はどこにもない**
- `config.php` は定数ガード付きなので直接アクセスでは 404
- CSRF トークン (`hash_equals` で比較)
- ログイン成功時に `session_regenerate_id(true)` — セッション固定化攻撃対策
- 30 分の無操作タイムアウト
- 失敗回数に応じた遅延 (最大 3 秒) — 総当たり対策
- Cookie は `HttpOnly` / `SameSite=Lax` / パスを `/synthlab_dev/` に限定。
  HTTPS なら `secure` も付く
- リダイレクト先 (`next`) は `^/synthlab_dev/` にマッチするものだけ許可 —
  オープンリダイレクト対策
- `Options Indexes` が有効なので、各ディレクトリに 404 を返す `index.php` を置いた

実測での確認:

| 操作 | 結果 |
|---|---|
| 未認証で `index.php` | 302 → `login.php?next=...` |
| 未認証で `doc.php?id=05-algorithm` | 302、**本文の漏れは 0 バイト** |
| 誤ったパスワード | 「違います」を表示、遅延あり |
| 正しいパスワード | 302 → 元の深いリンクへ復帰 |
| `next=https://evil.example/` | 拒否 |
| ログアウト後に再アクセス | 302 → `login.php` |

## 3. 検査項目カタログ

36 項目、9 グループ。各項目は

```php
'TG' => ['label' => '中性脂肪', 'unit' => 'mg/dL', 'dec' => 0, 'group' => '脂質',
         'ri' => ['M' => [40.0, 234.0, 100.0], 'F' => [30.0, 117.0, 65.0]]],
```

`ri` は `[下限 L, 上限 U, 中央値 M]`。`'A'` キーは男女共通。

### 3.1 パラメータ復元

論文 2 の「平均値と基準範囲だけが示されていれば分布が完全に推定できる」を
閉じた解として実装した (導出は [05-algorithm.md](05-algorithm.md) 2 節)。

$$
d = \frac{LU - M^2}{L+U-2M},
\qquad
\mu = \log(M-d),
\qquad
\sigma = \frac{1}{1.959964}\log\frac{U-d}{M-d}
$$

**退化時の扱い**: $|L+U-2M|$ が極小、あるいは $d \ge L$ になる場合は
$d = M - 20(U-L)$ に固定し、公表値である $L, U$ を厳密に再現するよう

$$
\mu = \frac{\log(U-d)+\log(L-d)}{2},
\qquad
\sigma = \frac{\log(U-d)-\log(L-d)}{2 \times 1.959964}
$$

とする。

### 3.2 カタログの検証結果

36 項目 × 性別 = **48 通りすべて**について、復元したパラメータから
$Q(0.025)$ と $Q(0.975)$ を計算し、入力した $L, U$ と比較した。

- **48/48 で相対誤差 $< 10^{-6}$**
- **48/48 で $d < L$** (lnorm3 の定義域を満たす)
- 中央値のずれは Alb のみ 0.14% (基準範囲が完全対称 4.1–4.6–5.1 のため
  退化経路に入る)。他は $< 10^{-6}$

### 3.3 カタログの出所について — 重要な注意

収録した基準範囲は、日本臨床検査標準協議会の共用基準範囲などの
**公開されている一般的な値**である。
**論文の付録データセット (Zenodo, doi:10.5281/zenodo.3841232) そのものではない。**

- 基準範囲 $(L, U)$: 公開値
- 中央値 $M$: **推定値**。右裾に歪んだ分布として妥当な値を採用した

したがって生成される値は「論文が推定したパラメータの再現」ではなく、
「論文の**方法**を公開基準範囲に適用した結果」である。
実際の研究用途では Zenodo のパラメータに差し替えるべきで、
差し替え箇所は `lib/catalog.php` の `ri` 配列 1 か所に限定してある。

## 4. 相関構造

### 4.1 エッジの構成

論文 2 の研究2 は実データ (TBA 102,830名, JIC 25,058名) から
分散共分散行列を推定し GLASSO ($\alpha=0.04$, エッジ約 50 本) で疎化した。
SynthLab は元データを持たないので、

1. 論文 2 の議論で**名前が挙がっているエッジ**
   (AST–ALT–$\gamma$GTP の強い正相関、HbA1c–随時血糖の強い正相関、
   eGFR と BUN/CRE の負相関、T.Bil–D.Bil の強い正相関)
2. 一般的な臨床検査の知見

から **59 本のエッジ**を明示的に与え、指定のないペアは 0
(GLASSO で切断された状態に相当) とする。

これは**論文の再現ではなく AI の構成物**である。
差し替え箇所は `lib/corr.php` の `synthlab_edges()` 1 関数に限定してある。

### 4.2 正定値化

手で並べた相関は矛盾する。とくに赤血球系は対数スケールで線形関係にある。

$$
\log\mathrm{Ht} = \log\mathrm{RBC}+\log\mathrm{MCV}+c_1, \qquad
\log\mathrm{MCHC} = \log\mathrm{MCH}-\log\mathrm{MCV}
$$

**Higham (2002) の交互射影法**で最近相関行列に射影する。

$$
R_{k+1} = P_U\bigl(P_S(R_k-\Delta S_k)\bigr)
$$

$P_S$ は固有値を $\epsilon$ 以上にクリップ (Jacobi 法で固有値分解)、
$P_U$ は対角を 1 に戻す。

**一様縮小 $R \to (1-\lambda)R+\lambda I$ との比較 (実測)**

| 項目数 | 一様縮小に必要な $\lambda$ | Higham の最大変化 |
|---|---|---|
| 13 | 0.066 | **0.024** |
| 25 | 0.105 | **0.046** |
| 36 | 0.268 | **0.110** |

36 項目では一様縮小だと全エッジが 27% 薄まるのに対し、
Higham は RBC–Hb ($0.90\to0.79$)、Hb–MCH ($0.35\to0.28$)、
Hb–Ht ($0.95\to0.89$) に変化が集中した。
**上の線形関係から予想される矛盾箇所そのもの**である。
矛盾していないエッジはほぼ保たれる。Higham を採用した。

### 4.3 キャッシュ

Jacobi 固有値分解を含むため 36 項目で約 0.84 秒かかる。
項目集合と強度が同じなら結果は決定的なので、
`sys_get_temp_dir()` に JSON でキャッシュする。**2 回目は 0.6 ms**。

## 5. 疾患プリセット

**論文にない要素。** 一般的な臨床知見に基づき AI が構成した参考値である。
効果の与え方は 3 通り。

| 指定 | 数式 | 意味 |
|---|---|---|
| `shift` | $\mu_i \leftarrow \mu_i + k\sigma_i$ | 対数スケールで $\sigma$ 単位の平行移動 |
| `sd` | $\sigma_i \leftarrow c\,\sigma_i$ | ばらつきの倍率 |
| `min` / `max` | $[a_i,b_i] \cap [\log(m-d_i), \log(M-d_i)]$ | 検査値スケールの診断閾値を切断区間に変換 |

**適用順序が重要である。** `shift`/`sd` で $(\mu,\sigma)$ を動かしてから、
その**シフト後の値**で $\pm5\sigma$ の窓を作り、最後に `min`/`max` と交差させる。
順序を逆にすると、シフトで平均が旧上限を越えたときに区間が反転して潰れ、
生成値が定数になる (実際にそのバグを踏んだ →
[08-devdiary.md](08-devdiary.md) 8.5 節)。

`min`/`max` を切断区間として課すのが要点である。
これにより「糖尿病なら HbA1c $\ge 6.5$」を保ちながら、
**相関を崩さずに**サンプリングできる (Gibbs が同時分布から引くため)。

収録プリセット: 疾患名なし (健常) / 2型糖尿病 / 慢性腎臓病 (G3b–G4) /
慢性肝機能障害 / 肝硬変 (非代償期) / 脂質異常症 / 鉄欠乏性貧血 /
急性炎症・感染症 / 高尿酸血症・痛風 / メタボリックシンドローム。

自由記入の「コホート名」も受け付けるが、こちらは
**CSV のヘッダコメントに記録するだけで分布は変えない**
(根拠のない数値操作をしないため)。UI にその旨を明記している。

### 相関行列は疾患によらず同一である

疾患効果は $\mu$ と $\sigma$ だけを動かし、**相関行列は疾患によらず同じもの**を使う。
相関が保たれるので連動が自然に出る (HbA1c を上げれば相関を通じて血糖も上がる)。

**論文には疾患別の相関行列は示されていない。**
研究2 が構成した分散共分散行列は、TBA (全科入院患者) と JIC (循環器内科) という
2つの施設・診療科のデータそれぞれについてのもので、
疾患ごとに分けたものではない。したがって疾患別の $\Sigma$ を用意する根拠となる
データを本ツールは持たない。

利用上の注意として、**疾患プリセットで生成したデータの項目間相関は
プリセットによらず同一**である点は把握しておく必要がある。
相関構造を検証する用途では、疾患プリセットの選択が相関に影響しないことを前提にする。

なお $\mu$ シフトだけでも整合した組み合わせは出る。
たとえば CKD プリセットは CRE を上げ eGFR を下げるので、
両者の負相関 ($-0.85$) を通じて矛盾しない値になる。

## 6. バックエンド (`backend/synthgen.cpp`)

`code/jamia26a.cpp` の数学的核心を引き継いだ**依存関係ゼロ**の C++17 実装。

### 6.1 `jamia26a.cpp` から引き継いだもの

- 精度行列 $Q$ による Gibbs (条件付き分散 $1/Q_{ii}$)
- 残差ベクトル $\mathbf r = Q(\mathbf z-\boldsymbol\mu)$ の差分更新
  ($m_i = z_i - r_i/Q_{ii}$)
- ランダム走査
- 切断正規サンプラの裾処理 (`lognormsf`, `logsum`, `logdiff`, `invlogsf`,
  $|\cdot|>8$ で対数スケールに切替、左裾は対称性で右裾へ帰着)
- Acklam 近似の `norminv`
- Cholesky 失敗時のジッタ 10 倍戦略
- 逆行列の検算 ($\max|\Sigma Q - I|$)

### 6.2 変更した点

| | `jamia26a.cpp` | `synthgen.cpp` |
|---|---|---|
| 依存 | Eigen, libconfig, libcsv | **なし** (標準ライブラリのみ) |
| 線形代数 | Eigen `LLT` | 自前 Cholesky + 前進代入で逆行列 |
| 乱数 | `mt19937` (32bit 種) | **`mt19937_64`** |
| ディレクトリ作成 | `std::system("mkdir -p")` | **廃止** (標準出力に書くのみ) |
| 入力 | libconfig ファイル + CSV | 標準入力の key/value テキスト |
| モード | 断面のみ | **断面 + 時系列** |

`std::system` を廃したのは、設定由来の文字列がシェルに渡る経路を
残さないため (公開サーバから呼ぶので)。
標準入力のみを受け、引数を取らず、シェルを経由しないので注入の余地がない。

### 6.3 時系列モード (論文 3 の実装)

$$
\mathbf z_0 = \boldsymbol\mu + L\mathbf w_0, \qquad
\mathbf z_t = \mathbf z_0 + fL\mathbf w_t + \boldsymbol\varepsilon_t
$$

$\mathbf w$ の各成分は $\Phi^{-1}(u)$ の逆関数法。
初期ベクトルは集団分布の切断区間に入るまで最大 64 回引き直し、
収まらなければ成分ごとに区間へ射影する。
$f$ は論文の設定 (10〜20%) を既定 10% とした。

### 6.4 入出力

標準入力の spec (key/value)、標準出力に CSV、標準エラーに診断。

```
seed 42
npat 1000
mode cross | series
burnin 400 / thin 1 / randomscan 1        (cross)
points 24 / sfrac 0.10 / noise 0.01 / interval 4.0   (series)
item <name> <unit> <mu> <sd> <d> <lo_z> <hi_z> <decimals>
corr <v1> ... <vn>        (n 行)
```

`lo_z`/`hi_z` は `inf`/`-inf` を受ける。

## 7. 検証結果

### 7.1 周辺分布の再現

TG (男性) $L=40, U=234, M=100$ → $(\mu,\sigma,d)=(4.6881, 0.4100, -8.6486)$。
20,000 サンプルの実測分位点:

| | 目標 | 実測 |
|---|---|---|
| $Q(0.025)$ | 40 | **40.6** |
| $Q(0.5)$ | 100 | **100.6** |
| $Q(0.975)$ | 234 | **232.4** |

### 7.2 相関の再現

13 項目、20,000 サンプル、対数スケール ($z$) で実測。
Higham 射影後の値を目標とする。

| ペア | 指定 | 射影後 | 実測 | 誤差 |
|---|---|---|---|---|
| RBC–Hb | 0.90 | 0.855 | **0.854** | −0.001 |
| Hb–Ht | 0.95 | 0.902 | **0.899** | −0.004 |
| AST–ALT | 0.80 | 0.760 | **0.752** | −0.008 |
| Glu–HbA1c | 0.70 | 0.665 | **0.653** | −0.011 |
| TG–HDL | −0.45 | −0.427 | **−0.417** | +0.010 |
| CRE–eGFR | −0.85 | −0.807 | **−0.793** | +0.014 |
| Na–Cl | 0.75 | 0.712 | **0.704** | −0.008 |

すべて誤差 $\le 0.014$。指定した相関が正しく注入されている。
なお**検査値スケールで測ると値が変わる** ($(5.16)$ の変換が入るため)。
$\sigma$ の大きい TG では差が大きい。

### 7.3 切断の遵守

切断区間を狭く指定した検査で、生成値が区間を外れないことを確認した。

### 7.4 精度行列の数値精度

$\max_{i,j}|\Sigma Q - I|$:
$n=3$ で $2.2\times10^{-16}$、$n=30$ で $1.8\times10^{-15}$。
ジッタは一度も必要なかった (`usedjitter 0`)。

## 8. 公開ツールの安全側の設計

公開・認証なしなので、次の上限と対策を入れた。

| 項目 | 値 |
|---|---|
| 患者数上限 | 20,000 |
| 時系列点数上限 | 500 |
| 出力セル数上限 (行 × 項目) | 400,000 |
| バックエンドのタイムアウト | 25 秒 |

- 検査項目名は**カタログのキーに存在するものだけ**を採用
  (入力文字列がそのまま spec に入らない)
- 数値入力はすべて範囲クランプ
- `proc_open` に**配列形式**で渡し、シェルを経由しない
- 乱数種は数字のみ受理。空欄なら `random_int` で生成し、
  結果ページに表示して**再現可能**にする
- 出力 CSV の先頭に「実在の患者データではない」旨と生成条件を
  コメント行で埋め込む

UI には次を明記した。

- 出力は架空の数値であり、診断・治療・臨床判断には使えない
- 疾患プリセットの効果量は論文には含まれず、一般的臨床知見に基づく参考値である
- 基準範囲カタログは公開値ベースで、論文の付録データそのものではない

## 7.6 サンプリング設計の修正 (重要)

当初の断面モードは**単一の Gibbs 連鎖の連続掃引を別患者として使っていた**。
これは誤りで、相関の強い高次元では隣接標本がほぼ同じになり、
全患者が中位値に張り付いた。あわせて Higham 射影の固有値クリップが
$10^{-8}$ で、相関行列がほぼ特異 (条件数 $10^9$) になっていた。
条件付き SD の下限が $0.0001\sigma$ まで潰れ、連鎖が動けなかった。

修正後の断面モードは**患者ごとに独立に引く**。

1. 無相関標準正規を逆関数法で引き $\mathbf z = \boldsymbol\mu + L\mathbf w$。
   切断がなければ厳密な標本で、患者間は完全に独立
2. 切断区間へ射影
3. 精度行列 $Q$ による Gibbs を `relax` 回 (既定 20) 回して切断つき分布へ緩和

固有値の床は $0.02$ に上げた (条件数 $10^9 \to 160$、相関の最大変化は
$0.046 \to 0.054$ にしか増えない)。
診断に患者間ラグ1自己相関 (`worstpatientlag1`) を出し、再発を検出できるようにした。
詳細は [08-devdiary.md](08-devdiary.md) 8.7 節。

また $d < 0$ の項目 (CRP など) で負の値が出ていたため、
$y \ge 0$ すなわち $z \ge \log(-d)$ を切断区間に加えた。

## 7.7 出力の列と性別の扱い

出力は次の列を持つ。

```
patient_id,sex,disease,disease_code,[cohort,][visit,week,]<検査項目...>
```

`sex` を意味のある値にするため、「男女混合」では
**男女それぞれの基準範囲で半数ずつ生成して結合する**
(バックエンドを性別ごとに1回呼ぶ)。
基準範囲を平均してから lnorm3 を当てはめる方式は、
男性の分布と女性の分布の**混合とは別物**なので採らなかった。

- ヒストグラムには混合密度 $0.5f_M + 0.5f_F$ を重ねる
- 「範囲内%」は各患者の性別に対応する基準範囲で判定する
- 行を全部配列に持たないよう、グループの CSV をなめながら
  属性列を前置して1行ずつ出力する (`sl_each_row()`)。
  要約統計・プレビュー・グラフ用データも同じ1パスで集める

## 7.8 波形表示

時系列モードでは論文 (MEDINFO 2025 Fig.1) と同じ形式で、
**項目ごとに1枚ずつ、実スケールの縦軸**で波形を描く
(横軸 = 初回検査日からの週数)。基準範囲は帯と破線で示す。

対象患者の線を濃く、**他の患者3名の線を薄く重ねる**。
これにより論文の主張 —「個人に着目すると検査値は分布のごく一部しか動かない」— が
線の高さの違い (個人差) と揺れ幅 (個人内変動) の対比として一目で分かる。

## 7.9 個人に着目した作りへの組み替え

元の研究の主眼は集団のデータセットを作ることではなく、
**目の前の1人の検査値を統計的にどう解釈するか**である
(論文2 の題は「血液検査値に偏差値をつける」、
論文3 の出発点は「個人に着目すると検査値は分布のごく一部しか動かない」)。
当初のツールは N 人生成が既定 (100人) で、この趣旨から外れていた。

### 既定を1人にした

入力画面の先頭に「1人を詳しく見る」/「N人まとめて出力」の選択を置き、
**前者を既定**にした。後者を選ぶと患者数の欄と注意書きが現れる。
注意書きの内容は、N人分の出力が本ツールが利便のために足した機能であり、
**集団としての疫学的な妥当性 (有病率・年齢構成・施設ごとの偏り) を
一切考慮していない**ことの明示である。

### 個人票 — 偏差値

1人モードでは各項目について
値・基準範囲・**偏差値** $T$・パーセンタイル・基準分布内の位置・判定を並べる。

$$
T = 50 + 10\,\frac{\log(x-d)-\mu}{\sigma},
\qquad
F(x) = \Phi\!\left(\frac{\log(x-d)-\mu}{\sigma}\right)
$$

基準範囲の下限が $T \approx 30.4$、中央値が $T = 50$、上限が $T \approx 69.6$ に対応する
(実測で厳密に一致することを確認した)。

**重要な実装上の判断**: $\mu, \sigma, d$ には
**疾患シフト前の「健常の基準分布」**のものを使う。
シフト後の分布で偏差値を計算すると「疾患群の中での相対位置」になってしまい、
「基準集団からどれだけ離れているか」という本来の意味が失われる。
そのため `sl_params()` は `rmu` / `rsigma` / `rd` として
疾患効果適用前の値を別に保持する。

`norm_cdf()` は自前実装である。PHP には `erfc()` が標準では無い
(stats 拡張が必要)。Zelen & Severo の近似
(Abramowitz & Stegun 26.2.17) を使い、既知の値との比較で
**最大絶対誤差 $7.0\times10^{-8}$** を確認した。
端に寄った値は `100.0%` と出さず `>99.99%` のように不等号で表示する。

### 個人内変動と集団分布の対比

1人・時系列モードでは、項目ごとに
**集団分布の密度 (灰) とその人の変動域 (青帯)** を重ねた図を出す。
論文3 の主張がそのまま図になる。

比は**対数スケールで見る**。生成モデルは

$$
z_t = z_0 + f L \mathbf w_t + \eta\,\sigma\,\xi_t
$$

なので個人内 SD は $\sigma\sqrt{f^2+\eta^2}$ になり、これが期待値である。
実測 (60回受診、$f=20\%$, $\eta=1\%$、期待 0.200) は 0.183〜0.228 で、
ずれの原因は2つ確認した。

1. **標本ゆらぎ** — $n=60$ で SD の標準誤差は $1/\sqrt{2(n-1)} \approx 9\%$。これが主因
2. **出力の丸め** — 小数桁の粗い項目では量子化が個人内変動と同程度になる。
   HbA1c で丸め後 0.256 / 丸めなし 0.228 と差が出た (`writez` で確認)

**出力スケールの SD 比は $f$ に一致しない。**
$f$ は $\log(y-d)$ の世界のパラメータなので、
歪んだ項目ではその個人が分布のどこにいるかで絶対 SD が変わる
(分布の左側にいる人ほど小さい)。当初この点を誤って
「出力スケールの比が $f$ 付近になる」と書いていたので直した。

## 8.1 クライアント側の落とし穴 (実際に踏んだもの)

公開ツールは**ブラウザで使われる**ので、サーバが 200 を返すことは
動作確認にならない。実際に利用者の環境で送信されない不具合を出した。

| 症状 | 原因 | 対策 |
|---|---|---|
| 送信ボタンが無反応・エラーも出ない | 非表示の欄 (`sfrac`) が HTML5 の `step` 検証で invalid。ブラウザは送信を拒否するが、非表示なのでエラーを表示できない | 実数欄は `step="any"`。さらに欄を隠すとき `disabled` も立てて検証対象から外す |
| 数式の一部が壊れる | MathJax slim 版 (`tex-svg.js`) が `\boldsymbol` の拡張を遅延読み込みし 404 | 全拡張同梱の `tex-svg-full.js` に差し替え |
| 生成後にトップへ戻れない | 戻るリンクは存在したが、CSV ボタンの隣と長いページ最下部にあり見つけられなかった | ヘッダに常時表示の共通ナビを置き、`lib/nav.php` にリンク一覧を一元化 |

いずれも**アクセスログで判明**した。前者は「ページの GET はあるのに
POST が 1 件もない」、後者は `assets/input/tex/extensions/boldsymbol.js` の 404。

検証手段も用意した。

- 配信中の HTML から全入力の `min`/`max`/`step`/`pattern`/`required` を取り出し、
  既定値と突き合わせて不整合を機械的に検出する
- `mathjax-full` を使った headless 組版で全文書の数式を実際に変換する
  (**全 9 文書 791 式、エラー 0**)

## 8.2 付帯機能

### メール通知

依存関係ゼロの SMTP クライアント (`lib/mailer.php`) を実装した。
STARTTLS / 暗黙 SSL / 平文、AUTH PLAIN / LOGIN に対応する。
PHPMailer 等を導入できない環境なのでソケットで直接プロトコルを話す。

要点:

- 応答は複数行に対応して読む (`250-` と `250 ` の区別)
- STARTTLS 後は **EHLO をやり直す** (AUTH の提示が TLS 後に変わる)
- 行頭のドットをエスケープする (dot-stuffing)
- 件名は日本語を RFC 2047 (`=?UTF-8?B?...?=`) で符号化し、75 文字で折る
- ヘッダ注入を防ぐため改行を落とす
- **認証情報はやりとりの記録に残さない**

設定は `synthlab_dev/config/mail.php` に base64 化 JSON + 定数ガードで保存。
**`www-data` が作成し `0600`** にするので www-data と root 以外は読めない
(`sanuki` からも読めない)。HTTP からは 404。

Gmail に対する実測で、接続 → EHLO → STARTTLS → TLS 確立 → 再 EHLO →
AUTH PLAIN → 535 (資格情報が不正) まで到達することを確認した。
**プロトコル実装は正しく、あとは正しい資格情報を入れるだけ**である。

### アクセス・生成ログ

`lib/usagelog.php`。1日1ファイルで、
**先頭に定数ガード + `__halt_compiler()`、その後ろに 1行 = base64(JSON)** を追記する。

この形式にした理由:

- 追記が $O(1)$ で済む (配列全体の読み書きが不要なので競合しにくい)
- 定数ガードで HTTP から 404。仮にガードを抜けても
  `__halt_compiler()` の後ろは PHP が出力しない (二重の保護)
- base64 なので利用者由来の文字列が行を壊さない

生成ログには**乱数種と項目一覧**を残すので、後から同じデータを再現できる。
`127.0.0.1` は記録しない (動作確認で埋まるため)。

### ソースコード閲覧

`source.php`。Apache が `/home/sanuki` を辿れないため、
`tools/publish-code.php` が各ファイルを base64 化して定数ガード付き PHP に包み、
`synthlab_dev/code/` に配置する。往復検証つき。

**文書 (nowdoc 方式) と違い、コードは base64 にした。**
理由は、ソース中に `$`・PHP 終了タグ・区切り子が現れるため。
実際、この仕組みの説明を書いているときに
**単一行コメント内の PHP 終了タグで PHP モードが終わる**という
言語の落とし穴を踏んだ (→ [08-devdiary.md](08-devdiary.md) 8.13 節)。

構文着色は自前。コメントと文字列を先にプレースホルダへ退避してから
語句を着色するので、文字列中のキーワードが着色される事故が起きない
(Markdown レンダラと同じ手法)。

## 9. 既知の限界

1. **相関行列が AI の構成物**である (4.1 節)。実運用では差し替えが必要
2. **中央値が推定値**である (3.3 節)。基準範囲は公開値だが中央値は公開されていない
3. **疾患プリセットに疫学的裏打ちがない** (5 節)
4. **時系列に自己相関がない**。論文 3 の方式をそのまま実装しているため。
   AR(1) 化の案は [05-algorithm.md](05-algorithm.md) 5.4 節に示したが、
   $\tau_i$ を決める根拠がないので実装していない
5. **年齢を扱わない**。論文 2 も今後の課題として挙げている
6. **項目ごとの時定数を持たない** (HbA1c が週単位で動いてしまう)
7. 疾患効果と切断区間の**適用順序**に注意が必要である。
   切断区間はシフト後の $(\mu,\sigma)$ から決めなければならない
   (順序を逆にすると区間が潰れて生成値が定数になる。
   → [08-devdiary.md](08-devdiary.md) 8.5 節)。
   区間が $0.02\sigma$ より狭くなった場合は結果ページに警告を出す
8. 断面モードは **Gibbs 単一連鎖の間引き**なので、
   サンプル間の独立性は `thin` の妥当性に依存する。
   既定は burnin 400 / thin 1 で、$n$ が大きく相関が強い場合は
   `thin` を上げる必要がありうる (現在は UI から変更できない)
